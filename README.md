# Travel Assistant Agent

Engineering-grade CLI travel-planning agent built with LangChain 1.x `create_agent` + LangGraph. Uses DeepSeek as the default LLM and is fully runnable offline via a deterministic fake model — no API key required in that mode.

---

## Architecture

```
CLI (typer)
  └─ build_runner(settings)
       ├─ resolve_model(settings)  →  FakeChatModel | DeepSeek via init_chat_model
       ├─ make_checkpointer(settings)  →  InMemorySaver | SqliteSaver
       ├─ JsonPreferenceStore(prefs_path)
       └─ Runner.stream / Runner.run
            └─ build_agent(model, tools, checkpointer, preferences_block)
                 └─ create_agent(
                      model=model,
                      tools=tools,           ← M6 tool list
                      response_format=TripPlan,   ← raw schema (AutoStrategy)
                      state_schema=TravelAgentState,
                      checkpointer=checkpointer,
                    )
```

**Structured output strategy.** `response_format=TripPlan` passes the raw Pydantic schema to `create_agent`'s `AutoStrategy`, which selects:
- `ProviderStrategy` for profiled models (real DeepSeek). **Note: the real DeepSeek strategy has not been verified end-to-end in this project.**
- `ToolStrategy` (tool-call fallback) for profile-less models — used by the fake model and confirmed working in all tests.

**State.** `TravelAgentState` extends LangChain's `AgentState` with a `trip_request: TripRequest | None` field populated by the `record_trip_request` tool via `Command` state update.

**Tools (M6).** `build_tools(store, user_id)` returns:
- `record_trip_request` — parses the user request into `TripRequest` and writes it to agent state via `Command`.
- 5 domain tools (flights, hotels, weather, attractions, budget) — read `TripRequest` from state via `ToolRuntime`.
- `save_preference` — writes a preference key/value to `JsonPreferenceStore` and returns a `Command`/`ToolMessage`.

Python ≥ 3.11 required.

```bash
make install        # creates venv and pip-installs in editable mode
cp .env.example .env
```

## Environment configuration

All settings are loaded by `travel_assistant.config.Settings` (pydantic-settings, reads `.env`).

| Variable | Default | Description |
|---|---|---|
| `DEEPSEEK_API_KEY` | _(none)_ | Required for real model runs; omit to use `--fake` |
| `TRAVEL_AGENT_MODEL_ID` | `deepseek:deepseek-chat` | Model identifier passed to `init_chat_model` |
| `TRAVEL_AGENT_FAKE_MODEL` | `false` | Set `true` to force the deterministic fake model |
| `CHECKPOINTER_BACKEND` | `memory` | `memory` (default) or `sqlite` for persistent short-term memory |
| `TRAVEL_AGENT_SQLITE_PATH` | `data/checkpoints.sqlite3` | SQLite path (only used when `CHECKPOINTER_BACKEND=sqlite`) |
| `TRAVEL_AGENT_PREFS_PATH` | `data/preferences.json` | JSON file for long-term user preferences |
| `LANGSMITH_TRACING` | `false` | Set `true` to enable optional LangSmith tracing |
| `LANGSMITH_API_KEY` | _(none)_ | Your LangSmith API key (only propagated if you provide it) |

## Fake model

The fake model is deterministic, makes no network calls, and always produces a minimal `TripPlan`. Enable it with `--fake` or `TRAVEL_AGENT_FAKE_MODEL=true`. It emits a single structured `TripPlan` tool call:

```
Summary: "Sample itinerary (deterministic fake model)"
Assumptions: ["Generated by the fake model; set DEEPSEEK_API_KEY and unset fake mode for real planning."]
```

---

## Real DeepSeek usage

Set `DEEPSEEK_API_KEY` in `.env` and run without `--fake`. The model ID defaults to `deepseek:deepseek-chat`; override with `TRAVEL_AGENT_MODEL_ID`.

If you run without a key and without `--fake`, the CLI exits with:

```
Cannot start: No DEEPSEEK_API_KEY set. Set it in the environment / .env, or
enable the deterministic fake model explicitly via TRAVEL_AGENT_FAKE_MODEL=true
(or the CLI --fake flag).
```

## CLI examples

```bash
# One-shot run with the fake model (no API key needed)
python -m travel_assistant plan --fake --once -m "3-day trip to Tokyo in June"

# Interactive session with fake model
python -m travel_assistant plan --fake

# One-shot run with real DeepSeek (DEEPSEEK_API_KEY must be set)
python -m travel_assistant plan --once -m "5-day Paris trip, mid-range budget"

# Resume a named thread (short-term memory)
python -m travel_assistant plan --fake --thread-id my-thread-123 -m "Add a museum day"

# Fresh thread (ignore any existing state)
python -m travel_assistant plan --fake --new -m "Weekend in Barcelona"

# Specify a traveler ID for long-term preference storage
python -m travel_assistant plan --fake --user-id alice -m "Beach holiday"
```

CLI flags for `plan`:

| Flag | Description |
|---|---|
| `--message / -m` | Trip request text; omit for an interactive session |
| `--user-id` | Traveler ID for long-term preferences (default: `"default"`) |
| `--thread-id` | Conversation thread ID (default: auto-generated UUID) |
| `--new` | Force a fresh thread even if `--thread-id` is given |
| `--fake` | Use the deterministic fake model |
| `--once` | Single turn and exit (requires `--message`) |

## Streaming mode

The agent is driven via `stream_mode="updates"`, which yields `{node_name: state_delta}` dicts. Each event is rendered by `format_stream_event` and printed to stdout as the agent runs. The final structured `TripPlan` is pretty-printed at the end of each turn.

---

## Short-term memory (checkpointer)

Short-term memory is provided by a LangGraph checkpointer keyed by `thread_id`. The default backend is `InMemorySaver` (no persistence across processes). Set `CHECKPOINTER_BACKEND=sqlite` to use `SqliteSaver` for persistence across CLI invocations.

Resume a previous conversation by passing the same `--thread-id`.

**Implementation note (CL-1):** The pinned `langgraph-checkpoint-sqlite==2.0.10` and `langgraph-checkpoint==4.1.0` have a metadata-serde API mismatch (`dumps`/`loads` vs `dumps_typed`/`loads_typed`). A documented adapter `_MetadataSerde` in `src/travel_assistant/checkpointer.py` bridges this gap. Aligning the dependency pins to eliminate the shim is tracked as **CL-1** in `docs/superpowers/plans/2026-05-18-travel-assistant-agent.md` (Post-M9 cleanup section) — do not start before M9 is complete and approved.

---

## Long-term memory (user preferences)

Long-term preferences are stored per `user_id` in a JSON file (`TRAVEL_AGENT_PREFS_PATH`, default `data/preferences.json`) via `JsonPreferenceStore`. The agent has a `save_preference` tool that writes key/value preference updates. Preferences are injected into the agent's system prompt at the start of each turn.

API: `load_user_preferences(user_id)`, `save_user_preferences(prefs)`, `update_user_preferences(user_id, updates)`.

## LangSmith tracing

LangSmith tracing is **optional** and not required for normal runs.

To enable:

```bash
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=ls-...   # your LangSmith API key
```

When `LANGSMITH_TRACING=true`, `configure_tracing(settings)` is called before the runner is built and the CLI prints `(LangSmith tracing enabled)`. LangChain/LangSmith auto-instruments from there. No key is ever hard-coded; only a user-supplied key is propagated.
